Importing the data, creating splits and folds.

This modeling code was created to explore data from the ASA’s Census@School project. While the full dataset has more variables, I’ve selected about a half dozen that were used in the Shiny application I created for the second project. More information on the dataset and how it was built can be found on the ASA’s website (link below) and you can take your students to the site to add their own responses to the survey.

The data originates from an expansive student census profile documenting baseline metrics such as school transit times preferred extra-curricular structures, digital usage baselines, and environmental profiles. Learn more at the https://ww2.amstat.org/censusatschool/.

First I want to pull in my Census at School data from 2026:

CensusSchool <- read.csv("data/CensusAtSchool2026.csv", na.strings = c("", "NA"))

Because this data is not administrative, like the datasets we used in class, where every cell had a value, we need to address the missing value issue. Regression models would handle this well by just pairwise removing observations with a missing value, but our random forests cannot handle these kinds of missing values, so I’m just going to preemtively remove them.

CensusSchool <- CensusSchool |>
  tidyr::drop_na(
    text_messages_sent_yesterday, doing_homework_hours, classgrade, gender, ageyears,
    travel_time_to_school, favorite_school_subject, home_occupants
  )
save(CensusSchool, file = "data/censusAtSchool2026.RData")

Creating Models

Honestly, the numeric variables in this dataset are not great as response variables to the other predictors, but I believe the goal here is proof of concept, and not statistical rigor. I have chosen two possible outcome variables: text_messages_sent_yesterday and doing_homework_hours. After tinkering with both of them, I decided to use text_messages_sent_yesterday as my response variable, and the reminaing variables as my predictors.

Regression Tree Model

Since I am not using a categorical outcome variable, I’m not going to use a classification tree, but a regression tree instead. Regression tress create decision points, often called splits, which determine how to split the data into groups which will minimize the residual’s sum of squares within each of the nodes which follow.

# Outcome Vars: text_messages_sent_yesterday, doing_homework_hours
# Predictor Vars: classgrade, gender, ageyears, travel_time_to_school, favorite_school_subject, home_occupants, role_model_type

tree_rec <- recipe(doing_homework_hours ~ classgrade + gender + travel_time_to_school + favorite_school_subject + home_occupants + role_model_type, data = CensusSchool_train) |>
  step_naomit(all_predictors()) |>
  # don't normalize the outcome, but do the rest:
  step_normalize(all_numeric(), -all_outcomes()) |>
  # create dummys:
  step_dummy(all_nominal_predictors())

tree_mod <- decision_tree(tree_depth = tune(),
                          min_n = tune(),
                          cost_complexity = tune()) |>
  set_engine("rpart") |>
  set_mode("regression")
  
tree_wkf <- workflow() |>
  add_recipe(tree_rec) |>
  add_model(tree_mod)

Here I have decided to use RMSE (Root Mean Squared Error) as my primary metric of performance. Text Messages Sent is a continuous numeric variable, which means RMSE is well suited to interpret results, and to penalize large prediction errors more heavilyt than Mean Absolute Error. Hopefully that will encourage the tuning to select a model that avoids large mispredicitions.
